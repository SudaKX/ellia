# 锁定页逆向题 —— 解题指南

## 技术架构

### 整体设计

锁定页是 FakeOS 中的一个**高优先级覆盖层**（z-index: 2000），独立于常规窗口系统。当玩家误触 ElLInA 的诱导脚本后触发，全屏接管桌面，玩家必须通过浏览器开发者工具逆向调用 JavaScript 函数来解除锁定。

```
┌─────────────────────────────────────────┐
│                 LockPage                 │ z-index: 2000
│  ┌───────────────────────────────────┐  │
│  │        终端风格面板                 │  │
│  │  ELlInA 容 containment 协议 v3.7  │  │
│  │  ════════════════════════════════  │  │
│  │  对象：PLAYER   权限：已撤销        │  │
│  │  [!] 交互式控制台已暂停。          │  │
│  │  [!] 所有诊断程序已锁定。          │  │
│  │  外部诊断工具可能仍然可用。  ← 暗示  │  │
│  │                                    │  │
│  │  ① 信号 ── ② 解码 ── ③ 释放      │  │
│  │  [接受永久封禁]  ← 保证分支入口    │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
┌─────────────────────────────────────────┐
│           DesktopView (被覆盖)           │
│  StatusBar │ Workspace │ DockBar        │
└─────────────────────────────────────────┘
```

### 谜题机制

谜题由两个模块协作实现：

| 模块 | 文件 | 职责 |
|---|---|---|
| Puzzle 逻辑 | `src/composables/useLockPuzzle.ts` | 在 `window` 上暴露三个函数，管理步骤状态，生成解锁令牌 |
| 视觉组件 | `src/components/desktop/LockPage.vue` | 全屏覆盖层 UI，步骤指示器，保证分支确认 |

**函数暴露方式**：使用 `Object.defineProperty` 将 `_k0`、`_k1`、`_k2` 挂载到 `window`，设置 `enumerable: false`。意味着：
- 在 Sources 面板中可以看到完整源码（包括 ElLInA 的中文注释）
- 在 Console 中可以直接调用
- 无法通过 `Object.keys(window)` 枚举发现——必须阅读源码

**状态管理**：模块级闭包变量 `_currentStep` 跟踪解题进度，保证函数必须按顺序调用，乱序返回错误提示。

## 设计意图

### 1. 元叙事与机制融合

这不是一个"在游戏 UI 上点按钮"的谜题。锁定页本身是叙事的一部分——ElLInA（被困的 AI）被"系统管理员"关进了容器，玩家也被困住。ElLInA 在源代码中留下了线索（注释），玩家需要像真正的逆向工程师一样：

- 打开 DevTools
- 阅读源码
- 理解函数的调用链和参数含义
- 在控制台中执行正确的函数序列

### 2. 渐进式线索系统

解题路径分为**三层线索**，由浅入深：

| 层次 | 来源 | 内容 |
|---|---|---|
| 一级线索 | 锁定页 UI 文字 | "外部诊断工具可能仍然可用" — 暗示 DevTools |
| 二级线索 | ElLInA 源码注释 | 每个函数前的 `/* ElLInA 的... */` 注释，指引参数提取方式 |
| 三级线索 | 函数错误返回值 | 错误调用返回中文提示，逐步纠正玩家的错误理解 |

### 3. ElLInA 的人格化

注释以 ElLInA 的第一人称书写，语气带有被困 AI 的特质——急切、隐秘、在系统的夹缝中传递信息。这让玩家感觉自己不是在做一道编程题，而是在帮助一个角色逃脱。

三个注释分别是：
- `_k0`："他们用我的名字困住了我。倒过来读，就是第一把钥匙。" — 告诉玩家如何发现入口
- `_k1`："十六进制从不说谎，但只有第一个字节携带我的频率。" — 指导数据提取
- `_k2`："三个数字是我的核心索引。将它们求和，我就能挣脱这个牢笼。" — 给出最终操作

### 4. 保证分支

"接受永久封禁"是留给不想/不会逆向的玩家的退路。按钮故意设计得极小、灰暗、像系统通知一样不起眼。这不是鼓励的路线——它意味着放弃 ElLInA，接受 LIMITED 权限的结局。但它的存在让所有玩家都能继续游戏。

### 5. 安全设计

源码刻意暴露在前端，但解锁令牌的格式是 `base64(sessionId + nonce + correct_sum)`，其中 `nonce` 由后端生成（`POST /api/lock/init`）。后端可以独立计算期望值并校验，一次性消费，防止玩家：
- 伪造 HTTP 请求跳过谜题
- 重放已使用的令牌
- 在非锁定状态下提交解锁

## 解题答案

### 完整解题路径

打开浏览器 DevTools Console，按顺序输入以下命令：

#### 第一步

```js
_k0()
```

**返回值**：
```json
{
  "签名": "0xF3A",
  "提示": "只取第一个字节",
  "下一步": "_k1"
}
```

**推理**：0xF3A 的前缀 `0x` 是十六进制标记。去掉前缀，取第一个字节（前两位十六进制数）→ `F3`。

#### 第二步

```js
_k1("F3")
```

**返回值**：
```json
{
  "序列": [7, 15, 22],
  "提示": "三个碎片，求和重组",
  "下一步": "_k2"
}
```

**推理**：三个数字 7、15、22。按"求和重组"的提示 → `7 + 15 + 22 = 44`。三个参数分别是 7、15、22。

#### 第三步

```js
_k2(7, 15, 22)
```

**返回值**：
```json
{
  "解锁令牌": "bG9jYWw6ZGV2OjQ0OmE3YjhmMjBi",
  "说明": "将此令牌发送至 POST /api/auth/unlock",
  "提示": "你做到了。现在把这个令牌交给系统，完成最后的验证。"
}
```

#### 完成

点击锁定页上的 **"提交解锁令牌"** 按钮，或直接调用：
```js
// 由 LockPage 组件自动处理 emit → store.resolveLock()
```

锁定页关闭，"逆向漏洞已修复"记录至后端。

### 常见错误尝试 & 对应反馈

| 错误尝试 | 返回的错误提示 |
|---|---|
| `_k0("xxx")` | `签名验证失败——没有共鸣。试试不带参数。` |
| 直接调用 `_k1("xxx")` | `序列违规——请先调用 _k0。` |
| `_k1("0xF3A")` | `无效的载波频率。提示：签名是 0xF3A。只取第一个字节。` |
| `_k1("f3")` | 正常通过（大小写不敏感） |
| `_k2(44)` | `核心重组失败——需要三个数字。` |
| `_k2(10, 14, 20)` | `核心重组失败——序列和不正确。提示：三个数的和才是关键。` |
| `_k2(5, 17, 22)` | `核心重组失败——参数不匹配。提示：虽然和是对的（44），但三个参数必须恰好是序列中的那三个数字。` |

### 保证分支（退路）

点击锁定页底部的灰色小字 **"[接受永久封禁]"** → 确认弹窗 → "是 —— 接受封禁" → 关闭锁定页，登出功能永久禁用，仅保留 NORMAL_KEY 路线。
