# 解谜活动平台开发说明

本文整理《解谜初版方案》中与平台开发直接相关的内容，作为后续实现、拆分任务和定义接口时的参考。未在方案中确定的内容会明确标注为“待定”。

## 1. 平台目标与路由

活动平台由入口站点 Kxpage 与主体验 FakeOS 组成：

| 路由 | 职责 |
| --- | --- |
| `/kxpage` | 活动入口。基于已有 Kxpage 增加异常内容、玩家标识、进入 FakeOS 的引导和进度重置。 |
| `/console` | FakeOS 主体验。提供登录、模拟桌面、虚拟文件系统、谜题窗口、ElLInA 演出和结局操作。 |

部署计划为同一 Nginx 实例下按路径路由不同站点。Kxpage 通过 LocalStorage 自动保存玩家标识；应提供账号注册或恢复标识的方式。未注册玩家清除 LocalStorage 后将失去进度。

## 2. 推荐技术边界

| 层级 | 技术/职责 |
| --- | --- |
| Kxpage | 在既有源码基础上修改，负责入口叙事与玩家标识。 |
| FakeOS 前端 | 单一 Vue 3 项目，负责全部视觉表现、窗口交互和调用后端 API。 |
| FakeOS 后端 | Python FastAPI，负责玩家、进度、文件、谜题、演出与统计等所有业务数据。 |
| 数据库 | SQLite，降低初期开发和部署成本。 |
| Web 服务器 | Nginx，根据 `/kxpage` 与 `/console` 分发请求。 |

原则：前端不持有权威的玩家进度、谜题答案或权限数据；所有可影响剧情、权限和结局的状态均由后端验证并持久化。

## 3. 核心玩家流程

1. 玩家由 Kxpage 的异常内容进入 FakeOS，并使用 ElLInA 提供的 `PLAYER` 账号登录。
2. `PLAYER` 账户下解决 CTF 文件题、代码题与解谜游戏，取得 `NORMAL_KEY` 的相关进度。
3. 隐藏的哈希缓存文件谜题可生成/揭示 `JDKTrigger` 账号的唯一凭据。
4. 使用 `JDKTrigger` 登录后，玩家获得完整文件访问权限，阅读开发日志和 ElLInA 运行日志，进行 Puzzle Hunt 与线下谜题，寻找 Sandbox 执行文件，取得 `HAPPY_KEY`。
5. 在访问特定关键文件后，ElLInA 可在共享区域创建诱导脚本；点击后会触发登出、切换至 `PLAYER`，并进入锁定分支。
6. 玩家可通过前端逆向关闭锁定页并回到登录页，之后必须登录 `JDKTrigger` 继续正线；接受“保证”则禁用登出能力，只能继续 `NORMAL_KEY` 路线。
7. 通过 Sandbox 管理界面提交 Key 并选择操作，后端根据 Key 权限与此前状态结算结局。

## 4. 账户、权限与关键状态

### 4.1 账户

| 账户 | 访问范围 | 主要内容 |
| --- | --- | --- |
| `PLAYER` | 受限虚拟文件访问 | ElLInA 演出、带提示的 CTF 文件题/代码题、解谜游戏、密码文件分段谜题。 |
| `JDKTrigger` | 完整虚拟文件访问 | 开发日记、ElLInA 运行日志、推理谜题、线下谜题、Sandbox 定位与最高权限 Key 路线。 |

`JDKTrigger` 的密码应按玩家动态生成，而不是作为固定公共凭据。

### 4.2 建议持久化状态

至少应记录以下状态，以支撑分支、存档与审计：

- 玩家 ID、注册/恢复身份信息、创建与最后访问时间。
- 当前登录账户、可登录账户、账户密码或凭据生成记录。
- 当前剧情节点、已解谜题、已读取关键文件、已触发演出。
- 已获得的 Key、Key 的权限等级与是否已使用。
- 锁定状态、是否已修复逆向漏洞、是否接受“保证”、是否永久禁用登出。
- 当前或可回退的 checkpoint。
- 最终结局与用于全局统计的结局操作。

状态转换必须由后端校验。不能仅通过前端隐藏按钮或修改 LocalStorage 限制路线。

### 4.3 Key 权限

| Key | 权限 | 预期结果 |
| --- | --- | --- |
| `NORMAL_KEY` | 可执行 Sandbox 的“解除”操作 | ElLInA 经由玩家释放，进入普通坏结局。 |
| `HAPPY_KEY` | 可执行“解除”或“清空”等最高权限操作 | 可导向删除 ElLInA 或释放 ElLInA 等不同结局。 |

对于提前输入尚未取得的 Key，应支持“谜题破坏者”结局或对应的剧情处理。

## 5. FakeOS 前端

### 5.1 顶层模块

FakeOS 前端包括四个顶层模块：

1. 登录界面。
2. 模拟桌面界面。
3. ElLInA 交互/演出界面。
4. 窗口框架。

### 5.2 桌面与窗口框架

桌面不需要传统桌面图标；通过状态栏展示已打开应用，并提供“所有应用”入口。应用以可并存的窗口形式呈现。

窗口框架至少支持：

- 创建、聚焦、关闭、最小化、最大化和恢复窗口。
- 拖动窗口，维护层级（z-index）与活动窗口状态。
- 状态栏中展示已打开窗口并允许恢复/切换。
- 应用总览页，按权限与剧情进度显示可打开应用。
- 全局消息机制，支持窗口间通信，以及剧情强制最小化或关闭窗口。
- 窗口尺寸和位置的合理默认值与视口约束，避免窗口脱离可见区域。

建议将框架拆为两个服务：

| 前端服务 | 职责 |
| --- | --- |
| `WindowService` | 管理窗口创建、销毁、聚焦、状态和窗口间消息总线。 |
| `APIClient` | 封装后端访问与认证上下文；以谜题唯一 ID 路由谜题相关请求，避免每个窗口自行构造请求。 |

### 5.3 内置窗口模块

| 模块 | 必需能力 |
| --- | --- |
| 文件资源管理器 | 展示虚拟文件树；按权限隐藏或拒绝文件；打开文件、选择打开方式、下载到本地；读取行为可触发剧情。 |
| 文本查看器 | 展示文本文件。语法高亮非必需。 |
| 图像查看器 | 展示图像文件，可作为图片类 CTF 题的载体。 |
| 音频播放器 | 使用浏览器音频能力播放音频文件；基础播放/暂停与进度控制即可。 |
| 通用答案验证器 | 提交答案、显示验证结果；可作为可执行文件窗口的统一表现形式。 |
| 交互式谜题 | 例如数独等网格题。界面只保留解题必须的交互，规则和提示由其他文件或剧情提供。 |
| 解谜游戏 | 纯游戏类谜题窗口，例如推箱子方向；具体机制待谜题设计确定。 |
| Sandbox 管理界面 | 输入 Key、展示当前可执行操作、提交最终操作并展示结局。 |

所有谜题窗口须与 FakeOS 保持一致的窗口样式和交互约定。谜题内容、可见性和答案判断不应由前端固定决定。

### 5.4 ElLInA 演出层

仅在 `PLAYER` 账户中出现，作为桌面上层的叙事与交互系统：

- 使用 ASCII 美术风格的 Canvas 进行画面表现。
- 支持大字幕、图片展示、抖动、动画和选项交互。
- 可以最小化所有窗口并临时替换状态栏为剧情选项。
- 建议分为基础绘图 Canvas 与 ASCII 后处理 Canvas 两层。
- 需要一个“演出脚本 -> 导演系统 -> Canvas/桌面动作”的执行模型。

演出 API 的具体形式待定，但至少应支持：显示/隐藏、文本、图像、动画、震动、选项、窗口控制和完成回调。

### 5.5 锁定页与前端逆向题

锁定页是独立于常规窗口交互的高优先级覆盖层：

- 第一次触发时，需提供未混淆且含 ElLInA 注释的 JavaScript 源码。
- 玩家通过浏览器开发者工具按顺序、以正确参数调用多个函数解除锁定。
- 解除后回到登录页，并将“逆向漏洞已修复”记录至后端。
- 此后错误登录 `PLAYER` 或在获得 `HAPPY_KEY` 后回去寻找 ElLInA，应进入不可逆锁定结局。
- 锁定页需提供“保证”分支，后端记录不可登出状态并将玩家导回普通路线。

逆向题源码可以刻意暴露在前端，但其最终状态变更必须通过后端一次性校验，防止直接伪造解锁请求。

## 6. 后端服务

方案将后端划分为逻辑服务，不要求实际拆分为独立微服务。初期可在单个 FastAPI 应用内按领域模块实现。

| 服务 | 职责 |
| --- | --- |
| 玩家标识服务 | 创建、恢复和识别玩家；关联 LocalStorage 标识、注册账号和服务器侧玩家记录。 |
| 文件服务 | 为不同账户和进度提供虚拟文件树、文件元数据、在线读取与下载；记录关键文件访问事件。 |
| 进度服务 | 管理剧情节点、分支条件、checkpoint、回退和不可逆状态。 |
| 演出服务 | 根据账号、进度和文件访问事件判定 ElLInA 演出；向前端提供演出脚本。 |
| 验证服务 | 校验谜题答案、游戏通关和 Key 提交；返回后续解锁项或状态转换。 |
| 统计服务 | 收集谜题完成、结局选择等聚合数据；支持活动最终统计。 |

## 7. 谜题模块框架

谜题模块是谜题相关数据的唯一来源。后端通过显式硬编码导入全部谜题模块，不需要动态发现机制。

每个谜题模块应能注册或提供：

- 谜题唯一 ID、名称、所属账户和解锁条件。
- 虚拟文件及其路径、MIME 类型、下载内容、访问权限。
- 谜题答案验证逻辑，或对游戏/交互状态的完成判定。
- 完成后的进度变更、后续文件或应用解锁项。
- ElLInA 演出脚本或演出触发条件。
- checkpoint 与统计项注册。
- 前端窗口所需的数据契约。

前端保持单一 Vue 3 项目。谜题模块不从后端下发任意 JavaScript 窗口代码；前端应维护“谜题 ID -> Vue 组件”的映射，以避免远程执行模块带来的构建和安全复杂度。

## 8. 文件系统与谜题支持

### 8.1 虚拟文件树

文件服务需要模拟路径、目录、文件名和权限，因为文件路径与目录结构本身也是谜题线索。至少支持：

- 按玩家、账号、进度动态展示目录与文件。
- 文本、图片、音频、压缩包/二进制及可执行谜题文件的元数据。
- 文件在线预览或选择应用打开。
- 二进制原始下载，供玩家使用本地工具分析。
- 指定文件/目录的访问审计与剧情触发。
- 公共文件区域中动态出现 ElLInA 诱导脚本。

### 8.2 哈希缓存文件谜题

该谜题用于发现 `JDKTrigger` 账户，设计为每位玩家得到不同答案。方案建议流程如下：

1. 在 `/download/cache/<hash-prefix>` 等路径提供伪装成哈希缓存的文件。
2. `cache.json` 为每个文件提供 `special_index`，指向哈希中的某一位；超范围索引表示干扰文件。
3. 合并有效索引字符得到一个哈希，以此定位包含分块表的文件。
4. 分块表内容经 Base64 编码，包含前后随机干扰及无效块。
5. 拼接有效块指定字节后得到 PNG 二维码。
6. 二维码内容为该玩家的后台用户、密码和权限表。

这一谜题的生成、文件内容、凭据和验证关系应完全由后端按玩家生成并持久化，避免重试或刷新导致谜题答案变化。

## 9. 数据模型建议

以下为实现时建议优先建立的实体，不限定 ORM 或表结构：

| 实体 | 关键字段 |
| --- | --- |
| `Player` | `id`、匿名标识、注册信息、创建时间、最后访问时间。 |
| `PlayerProgress` | 玩家 ID、剧情节点、当前 checkpoint、账户权限、不可逆分支状态。 |
| `PlayerCredential` | 玩家 ID、账户名、凭据哈希/生成信息、是否可登录。 |
| `PuzzleCompletion` | 玩家 ID、谜题 ID、完成状态、答案提交记录、完成时间。 |
| `FileAccessLog` | 玩家 ID、账户、虚拟路径、访问时间、是否为关键文件。 |
| `PerformanceState` | 玩家 ID、演出 ID、触发与完成状态。 |
| `Ending` | 玩家 ID、Key 类型、管理操作、结局 ID、结算时间。 |
| `GlobalStatistic` | 统计项 ID、聚合值或结局操作计数。 |

## 10. 关键 API 范围

具体路径待定，但 API 可按以下能力组织：

- 玩家初始化、注册、恢复身份。
- 登录、登出、获取当前账户与权限状态。
- 获取桌面状态、可用应用和已打开演出。
- 获取目录内容、读取文件、下载文件、记录文件访问。
- 获取或回退 checkpoint。
- 获取待触发演出和演出脚本；提交演出选项。
- 获取谜题数据、提交谜题答案、提交游戏完成状态。
- 获取 Sandbox 状态、提交 Key、获取可选操作、提交最终操作。
- 活动管理侧的聚合统计读取接口（如有需要，应独立鉴权）。

## 11. 实施顺序建议

1. 确定玩家 ID、进度状态机、账户权限与 checkpoint 数据模型。
2. 搭建 FastAPI、SQLite、基础鉴权上下文和 FakeOS Vue 3 工程。
3. 完成登录、窗口框架、状态栏和应用总览。
4. 完成文件服务与文件资源管理器、文本/图像/音频查看器。
5. 完成谜题模块注册机制、通用答案验证器及至少一个端到端谜题。
6. 实现 PLAYER/JDKTrigger 账户切换、关键文件访问事件和锁定分支。
7. 实现 ElLInA 演出脚本与导演系统。
8. 实现哈希缓存动态谜题、Sandbox 管理界面和全部结局状态校验。
9. 接入具体 Puzzle Hunt、线下谜题、交互谜题和解谜游戏。
10. 补充进度重置、统计、管理工具、端到端分支测试与 Nginx 部署。

## 12. 尚待确认的设计决策

- 最终剧情节点、所有分支条件、每个 checkpoint 的精确定义。
- 谜题总量、难度曲线、每题文件内容、交互方式和前端组件映射。
- Key 的生成和展示格式，以及提前输入 Key 时的精确判定规则。
- 锁定页逆向题的实际函数链、参数规则和公开源码范围。
- Sandbox 执行文件的虚拟路径、验证方式和最终管理操作列表。
- ElLInA 演出脚本的 JSON/DSL 格式，以及 Canvas ASCII 后处理算法。
- 账号注册、恢复进度和多设备访问的产品规则。
- 线下谜题的校园地点、可布置内容与活动组织流程。
- 全局结局统计是否真正影响志愿时长或 Kxpage 外观。
- 结局立绘、音频、图片和其他美术资产的版权与产出方式。
