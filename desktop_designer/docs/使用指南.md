# 出题器（Puzzle Designer）使用指南

FakeOS 解谜游戏的**出题后台**：出题者登录 → 出题 → 提交审核 → 管理员审核通过 → 发布 → 游戏端自动发现新题。

本项目包含两部分：

```
desktop_designer/
├── src/                  # 出题器前端（Vue3 + Vite + TS + Pinia）
│   ├── views/            # 登录、题目列表、出题/编辑
│   ├── stores/           # 账号（auth）、题库（questions）
│   └── config/api.ts     # 后端接入开关
├── server/               # 出题器后端（Node + Express + SQLite）
│   ├── src/              # 入口、认证、题目路由、数据库
│   └── .env.example      # 环境变量示例
└── docs/                 # 本文档
```

---

## 一、快速开始

### 1. 启动后端

```bash
cd desktop_designer/server
pnpm install          # 首次需要
pnpm start            # 默认 http://localhost:3000
```

首次启动会自动创建数据库（`server/data/questions.db`）并打印：

```
出题器后端已启动：http://localhost:3000
```

### 2. 配置管理员账号

后端启动时从环境变量自动创建管理员（**幂等**，重复启动不会覆盖）。

推荐方式：复制环境变量示例并修改

```bash
cd desktop_designer/server
cp .env.example .env   # Windows PowerShell: Copy-Item .env.example .env
```

`.env` 内容：

```env
PORT=3000
JWT_SECRET=请改成一段随机的长字符串
CORS_ORIGIN=http://localhost:5174
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123456
```

> 不配置 `.env` 也能启动：JWT 使用开发默认密钥、管理员需要手动执行
> `npm run seed-admin` 创建（默认账号 `admin / admin123456`）。
> **生产使用务必修改 `JWT_SECRET` 与 `ADMIN_PASSWORD`。**

### 3. 启动前端

```bash
cd desktop_designer
pnpm install          # 首次需要
pnpm dev              # 默认 http://localhost:5174
```

浏览器打开 `http://localhost:5174`：

1. 用管理员账号（如 `admin / admin123456`）登录
2. 出题者账号：页面右上角"注册"即可创建（默认角色为普通出题者）
3. 首个登录进系统的人如果是管理员，列表页会出现**审核**按钮

## 二、功能说明

### 登录 / 注册

- **登录**：使用已创建账号
- **注册**：新账号默认角色为普通出题者（`author`），只能操作自己的题目
- 管理员（`admin`）：查看全部题目、任意删除、审核通过/驳回

### 出题

「新建题目」进入编辑器，支持：

| 区块 | 说明 |
|---|---|
| 题目标题 | 必填 |
| 题型 | 单选 / 多选 / 填空 |
| 题面内容块 | 文本 / 图片 URL / 视频 URL / 富文本 HTML，可增删排序 |
| 选项 | 单选/多选题 2~10 个，勾选正确答案（多选可多选正确） |
| 填空答案 | 一个或多个空，顺序对应 |
| 提示 | 逐条揭示，可多条 |
| 答后解析 | 答对后展示（可选） |

右侧**实时预览**可边写边看效果；"测试预览"可实际作答，勾选"出题者视角"可高亮正确答案。

### 审核与发布

1. 出题者点「提交审核」→ 题目进入**待审核**
2. 管理员在列表中点「通过」或「驳回」（驳回可填原因）
3. **通过后**题目进入「已发布」，编辑已发布题目会自动回到待审核（需重新审核）
4. 管理员点「导出已发布题库」可下载 `published-questions.json`（也可直接复制）

### 游戏端自动发现（desktop）

审核通过的题目通过公开接口发布。游戏端（`desktop/`）在 `src/config/api.ts` 里：

```ts
export const USE_PUBLISHED_QUESTIONS = true                      // 打开自动发现
export const PUBLISHED_QUESTIONS_URL = 'http://localhost:3000/api/v1/questions/published'
```

打开后，游戏启动即拉取已发布题目并注册进谜题列表（`.puz` 双击 / 终端 `sil` 均可打开）。

## 三、后端 API 一览

基础地址：`http://localhost:3000/api/v1`；受保护接口需请求头 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/auth/register` | 注册（角色 author） | 公开 |
| POST | `/auth/login` | 登录，返回 `access_token` | 公开 |
| GET | `/auth/me` | 当前用户 | 登录 |
| POST | `/questions` | 创建草稿 | author |
| GET | `/questions/mine` | 我的题目 | author |
| GET | `/questions/all` | 全部题目 | admin |
| GET | `/questions/published` | 已发布题目（**公开只读**） | 匿名 |
| GET | `/questions/:id` | 单题详情 | 本人或 admin |
| PUT | `/questions/:id` | 编辑（已发布→回待审核） | 本人 |
| DELETE | `/questions/:id` | 删除 | 本人；admin 任意 |
| POST | `/questions/:id/submit` | 提交审核 | 本人 |
| POST | `/questions/:id/review` | 审核通过/驳回 | admin |
| POST | `/questions/:id/test` | 答案校验（不落库） | 本人 |
| GET | `/health` | 健康检查 | 公开 |

错误统一返回 `{ "error": "描述" }`，常见状态码：`401` 未登录、`403` 越权、`404` 不存在、`409` 状态冲突、`422` 校验失败。

## 四、配置说明

| 配置 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `USE_REMOTE_API` | `src/config/api.ts` | `true` | 是否连接后端；改 `false` 回退为纯前端本地模拟 |
| `QUESTION_API_BASE` | `src/config/api.ts` | `http://localhost:3000` | 后端地址 |
| `PORT` | `server/.env` | `3000` | 后端端口 |
| `JWT_SECRET` | `server/.env` | 开发默认值 | **生产必改** |
| `CORS_ORIGIN` | `server/.env` | `http://localhost:5174` | 允许的前端来源；前端端口变化时同步修改 |
| `ADMIN_USERNAME/PASSWORD` | `server/.env` | `admin/admin123456` | 启动时自动创建管理员 |

## 五、常见问题

**Q：前端提示"无法连接后端"？**
后端未启动，或 `QUESTION_API_BASE` 与后端端口不一致。先跑 `cd server && pnpm start`，再刷新页面。

**Q：前端端口不是 5174（被占用），跨域报错？**
前端实际端口变化时，同步修改 `server/.env` 的 `CORS_ORIGIN` 为实际地址（如 `http://localhost:5175`），重启后端。

**Q：忘记管理员密码？**
删掉 `server/data/questions.db` 后重启，或用 `.env` 重新配置管理员重新创建（幂等）。

**Q：切换回纯前端模式？**
把 `src/config/api.ts` 的 `USE_REMOTE_API` 改为 `false`（数据存 localStorage，适合单机演示）。

## 六、安全说明

- 密码使用 bcrypt 哈希存储，不存明文
- 接口使用 JWT（HS256）鉴权，密钥来自环境变量
- 权限逐接口校验（author 仅本人、admin 全量）
- 输入在后端二次校验（标题、选项数量 2~10、正确答案标记等）
- 生产部署时请：修改 `JWT_SECRET`、使用强管理员密码、按需限制 `CORS_ORIGIN`、通过 HTTPS 提供服务
